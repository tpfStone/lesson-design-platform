# 仓库管理说明

## 统一管理

本仓库采用单仓库结构，四个模块及根目录联调工具统一提交。它们是普通源码目录，不是 Git 子模块。日常在工作区根目录执行 Git 操作。

根目录 `.gitignore` 统一排除本地配置、业务数据、依赖环境、构建结果、备份和大批教学资料。模块内的 `.gitignore` 补充项目专属规则；配置模板、依赖锁文件、评分标准和固定测试样例仍应提交。

提交前可检查 `git status --short` 和 `git diff --cached --name-only`。新增本地数据目录时，应同步补充忽略规则。

## 原仓库历史

首次导入使用整理后的当前源码，GitHub 从新的总仓库提交开始记录。原 Lessongen 和 SimClass 历史未并入公开提交链，避免将旧运行数据和曾被跟踪的依赖环境带入新仓库。

原有开发历史完整保存在原机器的 `归档/代码备份/20261009-monorepo-git/`，包含 Git 元数据和经过验证的 bundle。整理前工作区快照位于 `归档/整理前快照/20261008-235220/`。这些恢复材料包含本地数据，不上传 GitHub。

历史对应关系：

- Lessongen 整理前检查点：`5287a96`；整理完成版本：`d277552`。
- SimClass 整理前检查点：`be9faef`；整理完成版本：`dbf6256`。

这些旧 SHA 属于本地保留的原仓库历史，不能直接在新 GitHub 仓库中查找。

## 业务数据与示例

运行数据库、会话记录、上传原件、评分与批注结果、教学资料全集、测试教案数据集由使用者单独保管。总仓库只保留实现所需的少量示例、评分标准和固定测试材料。

新机器需要按各模块说明重新安装依赖、填写本机密钥，并自行准备数据。不得将本地 `.env`、`data/.api_key` 或恢复快照补交到源码仓库。
