## 一、系统定位与核心范式

### 1.1 系统定位

面向中小学教学设计（教案）的 **AI 自动批注与评分系统**：输入一份教案 PDF/DOCX，系统自动完成学科识别、评分标准匹配、课标学段对照、多维度评分、逐条批注、改进建议生成，最终产出批注报告（DOCX）、评分清单（JSON/MD）、已批注 PDF 和横向对比表四类产物。

### 1.2 核心范式（四条设计主线）

| 范式 | 说明 | 解决的问题 |
|------|------|-----------|
| **标注示例驱动 Few-Shot** | 让 LLM 从人工标注范例中学习"标注思路、评语风格、评分逻辑"，再模仿标注新教案 | 通用提示词难以精确表达"什么是好的批注"，示例让评分风格可定制、可复现 |
| **双库对照检索** | 批注生成时注入"设计理论库"（36 条教学理论）+ "课标标准库"（数学 80 条 / 英语 77 条学段要求） | 让批注有理论依据和课标依据，而非 LLM 凭印象打分 |
| **建议/细化建议职责分离** | "建议"= 纯诊断（1-2 句点明核心问题）；"细化建议"= 具体改法（可操作步骤） | 诊断与处方分离，避免 LLM 输出含糊的"建议改进" |
| **批量生成降低 API 成本** | 所有非达标批注的细化建议打包为 **1 次** LLM 调用生成 | 原来每条批注 1 次调用（15-20 次/份），易卡顿且慢；现在 1 次/份 |

## 三、端到端数据流详解

### 3.1 单份教案流程（`--plan`）

1. **文档解析**：`parsers.parse_document()` 按扩展名分派（PDF 用 PyMuPDF 文本提取、DOCX 用 python-docx），返回全文文本。
2. **学科检测**：`detect_subject()` 用关键词匹配教案文件名与正文，识别学科（数学/英语/信息科技/语文…）。
3. **评分标准匹配**：`match_criteria_file()` 依据学科自动选择 `data/criteria/` 下对应标准文件；`--criteria competition|student` 切换比赛标准/学生自制标准。
4. **示例加载**：扫描 `data/examples/` 目录，加载标注示例（上限由配置 `max_examples=2` 控制，防止 token 超限），示例原文截断至 1500 字符。
5. **课标查询**：从教案文件名+正文前 300 字用正则提取年级（支持中文数字"四年级"与阿拉伯数字），映射到学段（1-2/3-4/5-6/7-9），从 `knowledge_base/math_structured.json` 或 `english_structured.json` 过滤出该学段全部课标条目，格式化为"课标对照"提示词块。
6. **提示词构建**：`prompts.build_user_prompt()` 组装为「标注示例 → 评分标准 → 课标对照 → 待评教案 → 输出格式约束」五段式用户提示词。
7. **LLM 评分**：`DeepSeekProvider.chat()` 调用 `deepseek-v4-pro`（temperature=0.1，max_tokens=16384），system prompt 为三选一提示词变体，输出强制 JSON。
8. **容错解析**：`safe_parse_json` 处理 LLM 输出中的中文标点（全角逗号/冒号）与格式瑕疵，解析失败时保留原始输出供排查（`debug_raw_output.txt`）。
9. **改进建议**：对每条非"达标"批注，用批注内容作为查询文本，同时检索设计理论库与课标库（`_match_sources`），标注依据来源类型（设计理论/课标标准/二者共同），再把所有待改进批注打包为 1 次 LLM 调用生成"细化建议"。
10. **输出**：按教案名建目录，生成批注报告 DOCX、评分清单 JSON/MD、已批注 PDF；保存 `debug_prompt.txt` 便于调试。

### 3.2 批量流程（`--batch`）

循环执行单份流程，全部完成后调用 `comparison.generate_comparison()`：
- 按"维度指纹"自动分组（数学组 / 英语组 / 信息科技组等，跨学科不混比）
- 输出 `batch_comparison.md`（总览表 + 分组维度表）与 `batch_comparison.csv`（Excel 可直接打开，utf-8-sig 编码）

## 四、模块详解

### 4.1 `pipeline.py` — 主入口与流程编排

CLI 参数：

| 参数 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `--list` | 标志 | 关 | 列出可用资源（示例/标准/教案） |
| `--plan` | 字符串 | 无 | 指定单份教案文件名 |
| `--batch` | 标志 | 关 | 批量处理 `data/plans/` 下全部教案 |
| `--criteria` | 字符串 | competition | 评分标准类型：competition / student |
| `--variant / -v` | 字符串 | default | 提示词变体：default / v2_guided / v3_strict |
| `--config / -c` | 路径 | config.yaml | 配置文件路径 |
| `--dry-run` | 标志 | 关 | 只构建提示词不调用 LLM |
| `--suggest` | 标志 | 关 | 生成改进建议（双库检索 + LLM） |

### 4.2 `parsers.py` — 文档解析

- `parse_pdf()`：PyMuPDF（fitz）文本提取，非 OCR；另有 `parse_pdf_with_annotations()` 提取 PDF 内已有批注。
- `parse_docx()`：python-docx 提取段落 + 表格。
- `parse_document()`：按扩展名分派，支持 `.pdf/.docx/.doc`。
- `parse_example()`：解析标注示例目录（`plan.pdf/docx + annotation.json`）。
- `detect_subject()` / `match_criteria_file()`：学科关键词检测与标准文件匹配。

### 4.3 `providers.py` — LLM 抽象层

- `create_provider(name, config)` 工厂：`deepseek`（现用）与 `openai`（预留）。
- `DeepSeekProvider`：基于 OpenAI SDK，`base_url=https://api.deepseek.com`；
  - `chat(system, user, temperature=0.1, max_tokens=16384)`：普通文本输出
  - `chat_json(...)`：额外设置 `response_format={"type":"json_object"}` 强制 JSON

### 4.4 `prompts.py` — 提示词工程

**三种 system prompt 变体**：

| 变体 | 定位 |
|------|------|
| `default` | 平衡版：学思路不抄内容、逐条对照标准、跨维度不重复扣分 |
| `v2_guided` | 引导版：强调工作流程（读示例→通读→对照→批注） |
| `v3_strict` | 严格版：拒绝模棱两可、敢于拉开分差、批注要有穿透力 |

**"建议"字段新定义**（v2.0 起）：
> 每条批注的"建议"只输出诊断结论，用 1-2 句话点明该条批注揭示的核心问题或缺失，禁止写修改方法。

**输出格式约束**（`OUTPUT_FORMAT`）：强制 12 维度完整 JSON 结构、评价字段五级制（优秀/达标/基本达标/部分达标/未达标）、每维度至少 2 条批注、总分 = 各维度得分之和。

### 4.5 `knowledge_base.py` — 设计理论知识库

- 来源：`E:\项目\教学设计理论.docx`（`THEORY_DOC_PATH` 环境变量可覆盖）
- 内容：**36 条教学理论条目，7 大类**（教学流程 13 / 方法模型 9 / 目标 5 / 框架 4 / 多媒体认知 3 / 评价认知 1 / 技术整合 1），如 ADDIE 模型、布鲁姆目标分类、逆向设计（UbD）、ARCS 动机模型、OBE 成果导向、抛锚式教学等。
- 构建：按"一、二、三…"大类标题切分 → 自动提取标题、关键词、摘要 → 结构化存储。
- 检索：`search_knowledge_base(query, kb, top_k)` — 关键词打分算法：关键词精确命中 +3、包含 +1、标题命中 +5、类别 boost +2，取 top_k。

### 4.6 `standards.py` — 课标标准库

- 数据来源：2022 版《义务教育数学课程标准》（189 页 OCR）与《义务教育英语课程标准》（201 页 OCR），再由 LLM 结构化清洗为 JSON（数学 80 条 / 英语 77 条，按学段×领域组织）。
- `query_standards(subject, grade)`：年级 → 学段映射（1-2/3-4/5-6/7-9），返回该学段全部课标条目，用于提示词注入。
- `search_standards(query, subject, grade, top_k)`：按查询文本与课标要求的字面重合度（bigram）打分，返回最相关的课标原文，用于建议生成的依据来源标注。
- 领域划分：数学 = 数与代数 / 图形与几何 / 统计与概率 / 综合与实践；英语 = 语言知识 / 文化意识 / 思维品质 / 学习能力。

### 4.7 `suggester.py` — 改进建议生成（v2.0 重构）

**双库检索**（`_match_sources`）：
```
查询文本 = 维度名 + 位置 + 具体分析
  ├─ 设计理论库（search_knowledge_base, top_k=2）
  └─ 课标标准库（search_standards, 按学科+学段限定, top_k=2）

依据来源 = 来源：设计理论 | 课标标准 | 二者共同
         + 理论：ADDIE 模型、布鲁姆目标分类…
         + 课标：[3-4年级|数与代数] 初步认识分数和小数…
```

**批量生成**：所有非达标批注 → 打包为 1 次 LLM 调用 → 返回 JSON 数组按 id 回填每条批注的"细化建议"。

### 4.8 `annotator.py` — 报告输出

- `generate_docx()`：批注报告 DOCX，每条批注包含：位置 / 原文 / 分析 / **建议（诊断）** / **依据来源** / **细化建议**，彩色区分。
- `generate_json()`：结构化评分清单（与 LLM 输出同构）。
- `generate_markdown()`：可读版评分清单 MD。
- 字段兼容：新字段 `建议`/`依据来源`，旧数据 `改进建议` 自动兼容读取。

### 4.9 `pdf_annotator.py` — PDF 可视化批注

- 高亮：`page.search_for` 五级兜底文本搜索定位原文，字级矩形精修（`_refine_rect_to_text`）。
- 便签：高亮区域重叠时改用便签（`add_text_annot`）；引用找不到时用右上角兜底便签。
- 跳过：引用文本过短（<4 字）时跳过。
- 去重：NM 标记追踪，避免同一位置重复批注。
- AI 描述性文字检测：全页面搜不到引用原文才判定为描述性内容（仅按引用查找，无模式匹配）。

### 4.10 `comparison.py` — 横向对比表

- `generate_comparison(results, output_dir, criteria_type)` → `(md_path, csv_path)`
- 按维度指纹分组（同学科同标准才可对比）；MD 含总览表 + 分组维度得分表；CSV 为 utf-8-sig 编码供 Excel 直接打开。

## 五、评分维度体系（12 维度，总分 100）

| 维度 | 分值 | 关注点 |
|------|:---:|--------|
| 教学内容 | 10 | 教材分析、知识前后联系、重难点把握 |
| 教学理念 | 5 | 核心素养、课标理念、数字技术融合 |
| 学情分析 | 5 | 学生认知水平、知识基础、学习困难 |
| 教学目标 | 5 | 目标定位、表述准确性、可测评性 |
| 教学资源 | 10 | 资源选用、数字技术应用、创新性 |
| 教学方法 | 10 | 方法适配性、自主学习、合作探究 |
| 过程设计 | 20 | 环节完整性、逻辑清晰度、时间安排 |
| 课程思政 | 5 | 思政元素挖掘、融合方式、持续性 |
| 课堂互动 | 10 | 互动形式、学生参与度、数字技术互动 |
| 评价反馈 | 10 | 评价方式、教学评一致性、反馈精准度 |
| 版式观感 | 5 | 布局合理性、图文搭配、可读性 |
| 文档规范 | 5 | 结构完整性、格式规范性、要素齐全 |

评价等级五级制：优秀 / 达标 / 基本达标 / 部分达标 / 未达标。

## 六、课标知识库构建流程

```
课标 PDF（扫描版）
   │  EasyOCR（CPU，约 12 秒/页，中文模型 100MB 存 E 盘）
   ▼
OCR 原始文本（math_kebiao_raw.json 189 页 / english_kebiao_raw.json 201 页）
   │  仅作参考备份，不参与运行时
   ▼
LLM 结构化（利用模型训练数据中的课标知识，2 次调用）
   ▼
结构化课标（math_structured.json 80 条 / english_structured.json 77 条）
   │  运行时由 standards.py 加载
   ▼
按学段检索 → 注入提示词 / 标注依据来源
```

关键技术决策：
- 曾尝试让 LLM 直接结构化 OCR 错字文本，失败（错字过多导致 JSON 解析率极低）；改为**直接利用 LLM 训练数据中的课标知识**生成结构化数据，准确率与效率都更高。
- OCR 模型（EasyOCR 100MB）与 Tesseract 数据均迁移至 E 盘，C 盘零占用。

## 十、关键设计决策与权衡

1. **Few-shot 用 2 份示例而非更多**：token 预算有限，2 份在"学到思路"与"成本"间取平衡；示例原文截断至 1500 字符。
2. **temperature=0.1**：评分任务需要一致性，低温度避免同份教案多次评分飘忽。
3. **建议生成从"逐条调用"改"批量调用"**：原每条批注 1 次 API（15-20 次/份，偶发卡死），改为 1 次/份，耗时与稳定性大幅改善。
4. **课标注入放在提示词中部**：作为"评分参照系"而非"评分标准"，避免与比赛标准冲突。
5. **年级检测失败时的策略**：教案文件名/正文无年级信息时不注入课标（如全英文标题的 At the farm），不强制兜底以免误配学段。
6. **JSON 容错**：LLM 输出中文全角标点时，统一清洗后再解析；解析失败保留原始输出便于排查。

## 十一、当前限制与后续规划

### 已知限制

| 限制 | 说明 |
|------|------|
| 课标库仅数学/英语 | 信息科技、语文等学科暂无结构化课标，无法课标对照 |
| 年级检测依赖文本 | 教案不写明年级时无法注入课标（可考虑书名号+单元号推断教材版本） |
| OCR 仅用于课标构建 | 教案正文 PDF 为文本型时直接提取；扫描版教案暂不支持 |
| 课标匹配为字面重合 | 偶有牵强匹配（如"目标模糊"批注匹配到统计领域课标），依赖 LLM 二次判断 |

### 后续规划

- [ ] 信息科技 / 语文课标结构化（复用 OCR + LLM 清洗流程）
- [ ] 年级智能推断（教材版本库：Unit 编号 → 年级映射）
- [ ] 建议的"诊断-处方"闭环校验（用 LLM 复查细化建议是否回应了诊断）
- [ ] 评分一致性校验（同教案多次评分取均值/方差告警）
- [ ] 对比表增加"较上次版本"增量对比（支持迭代修改教案后复评）
