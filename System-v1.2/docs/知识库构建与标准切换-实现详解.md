## 一、知识库构建

系统内置**两个**知识库，职责不同：理论库管"教学设计理论依据"，课标库管"教学内容是否符合课标要求"。

### 1.1 设计理论知识库（36 条）

#### 来源

- 一份 Word 文档：`E:\项目\教学设计理论.docx`（路径可通过环境变量 `THEORY_DOC_PATH` 覆盖）
- 文档结构：按"一、二、三、四、五…"分大类，每类下按"1. 2. 3.…"列条目

#### 构建流程（build_knowledge_base）

```
教学设计理论.docx
  │  ① python-docx 解析全文
  ▼
纯文本
  │  ② 正则切分大类：按"换行 + 一、二、三…、" 拆成 5+ 个板块
  │     一、→ 整体教学设计框架      二、→ 教学目标设计理论
  │     三、→ 教学流程与环节设计理论  四、→ 教学方法论模型
  │     五、→ 教学评价与认知理论
  ▼
各大类板块
  │  ③ 按子节切分：正则"换行 + 数字编号（1. 2. …）"拆成独立条目
  │     跳过 <50 字的碎片
  ▼
独立理论条目
  │  ④ 第一行为标题（去掉大类前缀和编号）
  │  ⑤ 正文前 600 字作为摘要
  │  ⑥ 自动提取关键词（见下）
  ▼
结构化条目
  {
    "id": "ADDIE模型",                          ← 标题去掉括号/英文后截 20 字
    "category": "整体教学设计框架",              ← 所属大类
    "title": "ADDIE 模型(ADDIE Model)",         ← 完整标题
    "keywords": ["分析","设计","开发","系统化"], ← 关键词（自动提取）
    "summary": "ADDIE是一个五阶段教学设计流程…", ← 摘要（前600字）
    "full_text": "完整原文…",                    ← 保留全文供溯源
  }
```

#### 关键词怎么来（_extract_keywords）

两部分合并，上限 15 个：

1. **标题拆词**：把标题里的中文词组提取出来（如"ADDIE 模型"→ 模型）
2. **教育学词表匹配**：内置约 60 个教育学术语（导入/探究/评价/核心素养/最近发展区…），出现在标题或正文前 800 字内则收录

#### 加载与缓存（load_knowledge_base）

- 首次调用时解析 docx 构建知识库，结果缓存到内存（`_kb_cache`），后续直接复用
- 实测解析出 **36 个条目**，分属 7 类（教学流程 13 / 方法模型 9 / 目标 5 / 框架 4 / 多媒体认知 3 / 评价认知 1 / 技术整合 1）

#### 检索算法（search_knowledge_base）

**关键词打分制**，不是向量检索（无需额外依赖）：

| 命中方式 | 加分 |
|----------|:---:|
| 查询关键词 **精确命中** 条目关键词 | +3 |
| 查询关键词与条目关键词 **互相包含**（模糊） | +1 |
| 查询关键词 **命中标题** | +5 |
| 查询关键词 **命中所属大类的热点词**（类别 boost） | +2 |

类别 boost 示例：查询含"互动/讨论/合作"时，"教学流程与环节设计理论"类条目额外加分；含"目标/素养"时"教学目标设计理论"类加分。

得分 > 0 的条目按分数降序，取 top_k（建议生成默认 2，最高 3）。

### 1.2 课标标准库（数学 80 条 + 英语 77 条）

#### 来源与构建（两阶段）

课标 PDF 是**扫描版**（无文本层），所以先 OCR 再交给 LLM 结构化：

```
阶段①  OCR（knowledge_builder.py，离线一次性，约 73 分钟）
  义务教育数学课程标准.pdf（189页）   义务教育英语课程标准.pdf（201页）
   │  EasyOCR（CPU，中文模型，约12秒/页，200DPI渲染）
   ▼
  math_kebiao_raw.json（0.3MB，115,672字）  english_kebiao_raw.json
   │  （原始 OCR 文本，含错字，仅作备份不参与运行时）
   ▼
阶段②  LLM 结构化（knowledge_gen.py，2 次 API 调用）
   │  思路：OCR 错字太多导致"让 LLM 清洗 OCR 文本"失败率极高，
   │       改为直接利用 LLM 训练数据中已有的课标知识生成结构化数据
   ▼
  math_structured.json（80 条）  english_structured.json（77 条）
```

#### 结构化数据的组织方式

按 **学段 × 领域** 组织，每条包含：

```json
{
  "学段": "3-4年级",          ← 1-2 / 3-4 / 5-6 / 7-9
  "领域": "数与代数",          ← 数学：数与代数/图形与几何/统计与概率/综合与实践
                               英语：语言知识/文化意识/思维品质/学习能力
  "要求": "理解小数的意义，会读写小数，能进行简单小数运算",  ← 完整能力描述
  "核心素养": ["数感", "运算能力"]
}
```

数学 80 条分布：4 个学段 × 20 条；英语 77 条分布：3-4 年级 23 / 5-6 年级 25 / 7-9 年级 29。

#### 运行时两个查询函数（standards.py）

**① query_standards(subject, grade) — 提示词注入用**

把教案年级换算成学段，取该学段全部课标：

```
年级数字 1-2 → "1-2"  3-4 → "3-4"  5-6 → "5-6"  7-9 → "7-9"
（支持传入"四年级"文本，正则提取数字 4）
```

结果经 `format_standards_for_prompt()` 按领域分组排版，追加到评分提示词末尾（约 1000 字）。

**② search_standards(query, subject, grade, top_k) — 建议依据来源用**

按查询文本与课标要求的**字面重合度**打分：逐 2 字滑窗（bigram），出现在课标文本里即 +1 分；优先在该学段内检索，取 top_k=2 条。

> 匹配效果示例（数学四年级，批注提及"小数"）：
> `[3-4年级|数与代数] 初步认识分数和小数,理解分母在10以内的分数的含义和一位小数的含义,会读写分数和小数。`

#### 为什么课标不是"全量注入"

- 全量 80 条注入会占用约 4000 token，且稀释重点
- 只注入**当前学段**的 20 条，让 LLM 聚焦"该年级该学什么"，判断教案是否超前/滞后/漏项
- 检索不到年级时（教案没写年级），不注入，不强行兜底

## 二、评分标准切换（竞赛 / 学生）

### 2.1 两套标准的存放方式

`data/criteria/` 目录下按"前缀区分类型、文件名含学科"组织：

```
competition_“田家炳杯”数学评价参考标准.docx   ← 竞赛标准
competition_“田家炳杯”英语评价参考标准.docx
competition_“田家炳杯”信息科技评价标准.docx
competition_“田家炳杯”语文评分参考标准.docx
student_评价指标V3.docx                        ← 学生自制标准
```

- **类型**由文件名中的 `competition` / `student` 决定，对应 `--criteria` 参数
- **学科**由文件名中的"数学/英语/信息科技/语文"决定

### 2.2 切换方式

```bash
python pipeline.py --plan "教案.pdf" --criteria competition   # 竞赛标准
python pipeline.py --plan "教案.pdf" --criteria student       # 学生自制标准
```

不传 `--criteria` 时，取 `config.yaml` 的 `prompt.default_criteria`（默认 `competition`）。

### 2.3 匹配逻辑（match_criteria_file）—— 三级降级

```
① 类型过滤：文件名含 "competition" / "student"
      │
      ├─ 只匹配到 1 份 → 直接使用
      │
      └─ 匹配到多份 → ② 学科匹配
            detect_subject(教案文件名 → 教案正文前2000字)
            找文件名同时含学科词（数学/英语…）的那份
                  │
                  ├─ 命中 → 使用该学科标准
                  └─ 未命中 → ③ 回退：使用第一份并警告
```

### 2.4 学科检测（detect_subject）—— 两级关键词

1. **文件名优先**：`SUBJECT_KEYWORDS` 关键词表，命中即返回（如"数学""英语""信息科技"）
2. **正文兜底**：内容关键词更具体，避免误判：
   - 数学："异分母分数""同分母分数""分数加减""几何""代数"…
   - 英语："PEP""Unit""Let's learn""At the farm"…
   - 信息科技："Python""scratch""算法""编程"…

### 2.5 切换后系统内部的变化

| 环节 | 影响 |
|------|------|
| 标准解析 | 不同 docx → 不同评分标准文本（`parse_document`） |
| 输出格式 | 竞赛标准固定 12 维度；学生标准维度数/满分由标准文件决定（`prompts.OUTPUT_FORMAT` 按维度动态生成） |
| 对比表 | 按"维度指纹"分组——**同学科同标准**的教案才放在一起对比，竞赛标准与学生标准的教案不会混比 |
| 提示词 | 标准全文注入提示词第二部分，作为逐条对照依据 |

### 2.6 一个具体例子

假设要批《陈密-四年级数学-小数的意义和读写.pdf》：

```
--criteria competition
  → 类型过滤：4 份 competition_* 都匹配
  → 学科检测：文件名含"数学" → 命中
  → 选用：competition_“田家炳杯”数学评价参考标准.docx

--criteria student
  → 类型过滤：只有 student_评价指标V3.docx 1 份
  → 直接选用
```

## 三、两个功能在流程中的位置

```
教案解析 → 学科检测 ──┐
                      ├─→ match_criteria_file（标准切换）
        --criteria ───┘
                              ┌──→ query_standards（课标注入提示词）
年级检测 → 学段映射 ──────────┤
                              └──→ search_standards（建议依据来源）
        --suggest ──→ 双库检索：search_knowledge_base（理论36条）
                                     + search_standards（课标）
```

## 四、如何扩展

| 想做什么 | 怎么做 |
|----------|--------|
| 加一份新评分标准 | 复制标准 docx 到 `data/criteria/`，文件名含 `competition` 或 `student`（及学科名）即可，无需改代码 |
| 加一门学科的课标 | 跑 `knowledge_builder.py`（改课标路径 OCR）+ `knowledge_gen.py`（新增学科配置），产出 `{学科}_structured.json` |
| 换理论库文档 | 设置环境变量 `THEORY_DOC_PATH` 指向新 docx，或直接覆盖 `E:\项目\教学设计理论.docx` |
| 调检索灵敏度 | 改 `search_knowledge_base` 的打分权重（+3/+1/+5/+2） |
