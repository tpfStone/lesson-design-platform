## 二、修复 1：设计理论库缺失

### 现象
同学端启动/评分时出现：
```
⚠ 理论知识文档不存在: E:/项目/教学设计理论.docx
⚠ 设计理论库为空，无法生成建议
```

### 根因
1. `knowledge_base.py` 的 `load_knowledge_base()` 中，理论文档路径**硬编码**为开发机的项目外路径
   `r"E:/项目/教学设计理论.docx"`，文件不存在时静默返回空库
2. 理论源文档（103 KB / 600 段落 / 36 条）从**未随包发布** → 交付包 `knowledge_base/` 只有 4 个 json
3. 下游 `suggester.py` 检测到空库后**直接 return** → "细化建议 + 依据来源"整块功能失效

### 改动
| 文件 | 位置 | 改动 |
|------|------|------|
| （资源） | `knowledge_base/教学设计理论.docx` | **新增**：从 `E:\项目\` 复制进项目（103,858 字节） |
| `knowledge_base.py` | 第 176-184 行 | 删除硬编码路径；改为**环境变量 `THEORY_DOC_PATH` → 按 `__file__` 推算项目内路径**（`knowledge_base/教学设计理论.docx`） |
| `tools/pack_release.py` | 第 104 行左右 | knowledge_base 复制白名单：`(".json")` → **`(".json", ".docx")`** |
| `tools/pack_release.py` | 第 22 行 | 版本号 `VER = "System-v1.1"` |

**改动后的路径逻辑**：
```python

    doc_path = os.environ.get("THEORY_DOC_PATH")          # 开发机可自定义
```

## 三、修复 2：复核标注页保存报错

### 现象
同学端「🔍 复核标注」页保存时报：
```
TypeError: unsupported operand type(s) for -: 'str' and 'int'
File "web/app.py", line 450, in page_review
```

### 根因
- 「系统得分」来自评分 JSON，是**数字**
- 「复核得分」由用户在 `st.data_editor` 中手填，可能被识别为**字符串**（如 `"8"`）
- 原代码 `(v - s)` 直接相减 → 类型错误
- 附带隐患：若用户留空（`""`）或填带单位（`"8分"`），直接 `float()` 还会抛 `ValueError`

### 改动（`web/app.py`，3 处）
| 位置 | 改动 |
|------|------|
| 工具区（`key_status()` 之后） | **新增** `to_number(x)`：安全转 float，兼容 `None`/`bool`/`NaN`/空串/带单位（"8分"）/非法值（"略"），一律不抛异常 |
| 第 448-451 行（报错处） | 差异计算重写：先用 `to_number` 转换；**留空或非法值跳过**；差值 `round(v - s, 2)`（避免浮点噪声） |
| 第 340 行 | 「得分率」计算同样加 `to_number` 兜底（同类隐患预防） |

**改动后的差异计算**：
```python
diffs = []
for r in edited:
    v = to_number(r.get("复核得分"))
    if v is None:                      # 留空 = 认可系统分，跳过
        continue
    diffs.append((r.get("维度"), to_number(r.get("系统得分")), v))
review["维度差异"] = [
    {"维度": d, "系统": s, "复核": v,
     "差": round(v - s, 2) if s is not None else None}
    for d, s, v in diffs
]
```

### 验证
| 验证项 | 结果 |
|--------|------|
| `to_number` 单元测试 | 10/10 通过（`8`/`"8"`/`7.5`/`"8分"` → 数字；`""`/`None`/`"略"`/NaN/True → None）✓ |
| 模拟 5 种输入场景 | 正常计算 2 条差异，无异常 ✓ |
| AppTest 5 个页面 | 全部 OK ✓ |

## 四、修复 3：细化建议整批丢失

### 现象
评完分后，批注报告里「细化建议」栏**整份教案为空**（评分、批注、依据来源均正常）。
历史统计：**62 份产物中 18 份缺失（失败率 29%）**，其中 09-03/09-04 那批 11 份全部缺失。

### 根因
1. 系统一次性向模型索取**全部建议**（JSON 数组，20-37 条、3795+ 字）
2. 模型在建议文本中偶用**未转义的英文双引号**，例如：
   ```json
   {"id": 9, "具体建议": "...完成学习单"我的检验方法"一栏并与同桌交流..."}
                                 ↑ 提前闭合字符串，破坏整个 JSON
   ```
3. 解析代码是裸 `json.loads(m.group(0))`，**无任何容错** → 解析失败 → 落入 except
4. 失败仅打印一行警告，**不影响评分主流程** → 静默降级，产物看起来"正常"，只是建议为空

### 改动（`suggester.py`，4 处）
| # | 位置 | 改动 |
|:--:|------|------|
| 1 | 系统提示词（输出格式段） | 输出格式改**对象** `{"建议列表": [{"id":1,"具体建议":"..."}]}`；新增"引用一律用中文引号「」/“”，**严禁使用英文双引号**" |
| 2 | 用户提示词（末尾） | 同上：对象格式 + 再次强调禁用英文双引号 |
| 3 | 新增 3 个函数 | `_sanitize_suggestions_json()`：把「具体建议」值内未转义英文双引号启发式替换为中文引号（判据：值以 `"}` 结尾）<br>`_extract_json_block()`：从杂质输出中提取 JSON 片段<br>`_parse_suggestions()`：**三重容错**——直接解析 → 提取片段 → 消毒重试；兼容对象/数组/代码块包裹 |
| 4 | 调用与解析段 | `provider.chat` → **`provider.chat_json`**（结构化输出，`response_format=json_object`）；解析改用 `_parse_suggestions`；**失败自动重试一次**；仍失败则明确提示 + 保留原始输出到 `output/debug_suggest_raw.txt` |

### 验证
| 验证项 | 结果 |
|--------|------|
| 单元测试（6 例） | 6/6 通过 ✓<br>①真实坏样本（值内 `"我的检验方法"`）→ 成功解析 3 条、内容完整<br>②正常数组 ③新对象格式 ④markdown 包裹 ⑤值内多组引号 ⑥无法解析→返回空 |
| **旧逻辑对照** | 同一坏样本下旧代码报 `Expecting ',' delimiter: line 3 column 69`——**精确复现**了线上失败（9-29 实测为 line 10 col 69，同类问题）|
| 端到端（之前失败的教案）| 《六年级 Unit2 Last weekend》：**修复前 0 条 → 修复后 25/25 条全部非空** ✓ |
| 格式源头约束 | 模型输出已改用中文引号「」，且返回 `{"建议列表": [...]}` 结构 ✓ |
| 包内校验 | 坏样本解析 2/2 ✓ |
