## 一、验收结论

本轮完成了 **System-v1.2 能力 + 已验收 `platform_api.py` 壳** 的接口级合并，未修改 F2/F3/F4。

核心结论：

- 保持原 5 个 `/internal/v1/...` 接口路径不变；
- 保持现有请求字段不改名、不删除；
- 固定平台口径为 `student + v2_guided`，`suggest` 默认开启；
- 返回 6 个一级维度、12 个二级维度；
- 二级维度与批注评价统一为 A/B/C；
- API 和导出产物使用 12 维得分重新求和后的总分；
- `rubric.groups` 保留，同时新增 `rubric.dimensions`；
- JSON、批注报告 Word、已批注 Word 的生成链路已做本地生成验证；
- OCR 源码与说明保留，EasyOCR 不作为本轮默认依赖。

## 四、真实产物生成测试

使用真实 `python-docx 1.2.0` 生成器对一份测试 DOCX 执行产物生成，结果：

- 批注报告 Word：生成成功；
- JSON 评分清单：生成成功；
- 已批注 Word：生成成功；
- 原生 Word 批注共写入 12 条，测试输出显示 12 条均完成精确定位。

因此将 `requirements.txt` 中 `python-docx` 最低版本从 `>=1.0` 提升为 `>=1.2.0`，避免旧版本缺少 `Document.add_comment()` 导致“评分成功但已批注 Word 失败”。

## 七、未做“假验收”的部分

当前执行环境没有可用的外网模型调用条件，因此没有在本轮直接调用真实 DeepSeek 完成一次完整 LLM 评分。接口契约、评分后处理、状态机、产物生成与下载链路均已分别验证；交到你的 Windows 项目环境后，仍建议使用你现有的 DeepSeek Key 再跑 **1 份真实教案** 做最终现场验收。

另外，统一 Web 页面属于总项目（F2 母版）范围。你已经明确要求本轮不修改 F2/F3/F4，因此这里不会为了“勾选第 10 项”而越界修改总前端。下一阶段只需让总 Web 使用 `rubric.dimensions` 绘制 12 维雷达图，并使用 `rubric.groups` 做 6 个一级维度摘要卡。

## 八、建议的现场最终验收顺序

1. 在 F1 目录安装/确认依赖：`python -m pip install -r requirements.txt`；
2. 启动：`python -m uvicorn platform_api:app --host 127.0.0.1 --port 8002 --http h11`；
3. 打开或请求 `/internal/v1/health`；
4. 从统一平台提交 1 份真实 DOCX 教案；
5. 检查任务最终为 `COMPLETED`；
6. 检查 6 组、12 维、A/B/C、总分；
7. 分别下载 JSON、批注报告 Word、已批注 Word；
8. 最后在总平台窗口完成 12 维雷达图 UI 验收。
