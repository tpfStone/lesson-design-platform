# Contributing

## 开发原则

- 不使用硬编码或 Mock 教案冒充真实模型结果；
- 模型输出必须经过 Pydantic、领域规则和引用完整性校验；
- Judge 只提供内部质量信号，不直接控制流程，也不替代人工实验；
- 优化必须能指出字段级真实变化，评分波动不算优化；
- 新增 Prompt 必须版本化，并在 trace 中保存版本与 SHA-256；
- 任何包含用户内容的测试材料都必须脱敏。

## 提交流程

1. 从独立分支开发；
2. 更新相关 Spec、契约和测试；
3. 运行 Python、Java、Vue 离线测试；
4. 检查 `git diff --cached` 与敏感信息；
5. 在 PR 中说明行为变化、验证结果和已知边界。

格式与测试命令见根目录 [README.md](README.md)。真实 API 运行会产生费用，不应放入普通 CI。
