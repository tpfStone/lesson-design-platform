# 前端体验基线（2026-09-24）

## 已核实

- 技术：Vue 3、Vue Router、Pinia、Vite、现有 CSS；路由切换已有 Vue `Transition`，移动端和 `prefers-reduced-motion` 已有基础规则。无需迁移框架才能改进体验。
- 视觉：暖纸色背景、深墨色文字、青绿色主操作和宋体教案正文已经形成辨识度。保持这套语汇，调整密度、层级、反馈和细节。
- 工作台：两条主路径清楚，但大幅装饰图占据首屏；近期任务请求失败会落入与“没有任务”相似的空状态，缺少可见的重试入口。
- 生成页：只需科目、年级、课题即可开始；手机端四组字段形成很长的单列页面，用户难以知道自己已填到哪一步。教学依据和可选字段的价值尚未在填表位置解释充分。
- 优化页：支持 Word 上传与检查；界面应更明确区分“上传原稿”“系统解析/导入基线”和“实际改写交付稿”，并提前说明原 Word 排版不保留。
- 运行页：展示阶段、轮次和进度；后续必须继续坚持仅根据真实事件更新，不制造连续增长的假百分比。
- 结果页：正文、八维内部质量、修改和复核清单都有，但 JSON Pointer 等工程术语会直接出现在教师视角；移动端评分图和长正文可能把“实际改了什么”推得很远。高分视觉不能盖过内容是否变化的事实。
- 浏览器 E2E、Vitest、截图采集脚本已存在。已有截图在 `web/docs/ui-audit/`，可作为视觉回归基线，但这些截图不代表真实用户研究。
- 本轮生产构建中入口 JS 约 65.68 KB gzip，结果页 `JobView` JS 约 167.39 KB gzip；这是构建产物大小，不是实测下载时间。结果页依赖较重，应在 S4 查明是否可按需加载图表。

## 尚未验证

- 真实教师/师范生完成任务的时间、误解率和满意度；不得把下面的目标值说成实测结果。
- 弱网、辅助技术、320 px 宽、浏览器放大至 200% 的完整验收。
- 真实用户设备上的 Core Web Vitals；本地构建大小和浏览器测试只能做工程代理指标。

## 范围边界

本规格不改变模型质量、教案内容契约、后端阶段定义或收费策略。发现后端数据不足时，先在 UI 诚实显示“未知/待确认”，再独立提出契约变更，不由前端推测结果。
