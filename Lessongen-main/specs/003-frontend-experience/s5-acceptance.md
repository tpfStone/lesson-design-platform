## 自动化结果

在 `web/frontend` 运行：

- `npm run typecheck`、`npm run lint`、`npm run format:check`：通过。
- `npm test`：7 个文件、23 条单元/组件测试通过。
- `npm run test:e2e`：Microsoft Edge 中 32 条浏览器流程通过，包含生成、优化、运行、失败、结果、网络异常和竞态。
- 生产构建差异预算：入口 JS gzip 约 67.8 KB（≤ 80 KB）；结果主块约 13.8 KB（≤ 25 KB）；延迟图表约 1.0 KB（≤ 5 KB）。这些是构建体积，**不是** LCP/INP/CLS 实测。

视觉截图来自脚本注入的模拟任务，不是模型服务实跑：[工作台桌面](./evidence/01-dashboard-desktop.png)、[生成页桌面](./evidence/02-generate-desktop.png)、[运行中手机](./evidence/14-running-mobile.png)、[优化结果手机](./evidence/09-optimize-result-mobile.png)、[优化失败手机](./evidence/12-optimize-failed-mobile.png)。

## 仍需真实环境验收（S5-07）

1. 连通真实 Java/MySQL/Python/模型服务，分别走生成、外部 Word 优化、失败恢复、待复核、未修改五类任务；核对后端契约与页面文案、下载文件。
2. 使用真实屏幕阅读器完成键盘任务流，并在浏览器原生 200% 缩放下检查提交、结果、下载。自动化的 ARIA/视口检查不能替代这一步。
3. 让目标教师独立完成一次生成和一次优化，记录是否理解“未修改/待复核/恢复记录/内部评分”及主要卡点。
4. 公开部署后分别采集移动端、桌面端真实访问 p75 LCP/INP/CLS；未拿到数据前不声明性能目标达成。大 Word 本地哈希在低端设备上的 INP 也待专测。

本批仅改变前端行为和体验，没有修改教案模型、后端 API 或数据库。发布门槛未通过前，不把模拟截图和内部评分当作教学效果证据。
