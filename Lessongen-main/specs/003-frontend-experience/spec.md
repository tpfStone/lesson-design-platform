# 产品与交互规格

## 1. 北极星目标

一位准备上课的教师，打开网页后可在 30 秒内找到“生成”或“优化”入口；最少信息能直接启动，补充教材/课标时理解其作用；离开运行页后仍能找回任务；结果页首先读懂“是否形成可交付版本、实际改了什么、哪些必须人工复核”。“30 秒”是待用户测试验证的目标，不是当前事实。

## 2. 用户任务与成功信号

| 场景 | 用户希望完成的事 | 界面必须回答 |
| --- | --- | --- |
| 从零生成 | 快速给出课题，按需补充依据 | 必填什么、可选资料有什么价值、是否会调用付费模型 |
| 上传优化 | 把已有 Word 变成可比较的修改稿 | 上传是否安全、原稿是否读懂、是否真正修改、原格式是否保留 |
| 等待运行 | 不必盯屏也不会丢任务 | 当前真实阶段、是否还在工作、何时可以回来 |
| 查看结果 | 决定是否试教或继续修改 | 交付版本、内容差异、未解决项、评分的边界和下载文件 |
| 出错恢复 | 知道下一步 | 是网络/服务/文档/模型问题，哪些内容仍可取回，如何重试 |

## 3. 必须满足的需求

- `UX-01` 导航：桌面及 320–1440 px 宽都能到达生成、优化和历史任务；当前入口有文字或非颜色的状态提示；键盘可见焦点。小屏不依赖 hover。
- `UX-02` 工作台：首次访问、任务加载中、真正空列表、筛选无结果、加载失败分别呈现不同文案和操作。失败不能伪装成空列表；重试不清除已有列表。
- `UX-03` 输入：必填/可选清楚；长表单有分组进度或目录，错误应指向具体字段；自动保存状态与提交状态不同。折叠区有错误时不得藏住它。
- `UX-04` 优化上传：区分文件检查、解析、审查、改写、交付；上传原件、候选稿与最终交付稿的标签不能混用。
- `UX-05` 运行：阶段、轮次、调用量只显示真实数据；缺失数据写“暂不可用”；刷新或离开后能继续查看。装饰动画不改变业务含义。
- `UX-06` 结果：首屏优先给出交付状态、Word 下载和“内容是否实际变化”；优化报告以教师语言显示主要修改、未解决项和原稿对比入口。内部八维分数为辅助信号，不作正式效果声称。
- `UX-07` 无障碍：所有交互可键盘到达，表单 label/错误关联，状态不只靠颜色，焦点可见；`prefers-reduced-motion` 下没有非必要位移或循环动画。
- `UX-08` 性能：优先系统字体和 CSS/Vue 原生能力，避免为简单入场动效增加整站 JS；较重图表只在结果区需要时加载。定义构建体积基线后再设差异预算。
- `UX-09` 响应性目标：公开部署后分别以移动端和桌面端真实访问的 p75 INP ≤ 200 ms 为目标；在取得实测数据之前，只记录为待验证指标，不能拿本地 E2E 代替。

## 4. 验收门槛

1. 在 320、390、768、1280、1440 px 检查核心页，没有横向滚动或遮挡关键操作；200% 浏览器缩放下仍能完成提交和下载。
2. 用键盘完成从工作台到生成表单提交、优化上传、结果下载；焦点位置可见。
3. 系统/浏览器减少动效设置下，界面立即切换状态，且仍能辨识加载、成功、失败。
4. 近期任务接口失败时出现“暂时无法读取近期任务”和重试；重试成功后恢复列表。空列表显示不同说明。
5. 浏览器 E2E 覆盖生成、优化、运行、失败和结果；至少一条针对新增状态或交互的回归测试。
6. 每个阶段有前后截图及人工检查记录，必要时进行小范围教师走查。页面截图只证明布局，不证明真实教学效果。

## 5. 非目标

- 不移植 React/换设计系统，不为了“动效”加入三套动画库，不在 P1 未验收前改变核心 API。
- 不做虚假的完成时间预测、假分数增长、假修改高亮或自动播放式营销首屏。
- 不复制上传 Word 的原版式；交付稿仍使用统一教案版式，但明确告知用户。
