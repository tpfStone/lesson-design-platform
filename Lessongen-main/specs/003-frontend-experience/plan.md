# 实施计划与技术选择

## 技术选择

保留 Vue 3 + Vue Router + Pinia + 现有 CSS。简单路由、列表和状态过渡使用 Vue 原生 `Transition` / `TransitionGroup` 与 CSS 变量，不增加运行时依赖。若后续确需跨组件共享布局或手势动画，再用独立样例评估 Motion for Vue 或 VueUse Motion，并比较体积、无障碍和维护成本；不把试验库直接灌入主站。View Transition API 只作为渐进增强候选，不能成为导航必要条件。图表若影响首屏，按结果页懒加载或降级为数值表。

## S0 · 可信状态与基础约束（本轮起步）

1. 固定现有页面截图、构建大小和浏览器测试为基线。
2. 增加统一动效时长/缓动 token；已有减少动效规则继续兜底。
3. 修正工作台近期任务的加载/空/筛选空/失败状态，给失败重试入口与浏览器测试。
4. 修正窄屏导航的触控目标与布局，不靠缩小字号解决。
5. 验收：类型检查、格式、Vitest、浏览器 E2E、320/390/1280 px 截图。

## S1 · 工作台与信息层级

保留两条核心入口，但降低装饰图区对任务入口的竞争；让最近任务更靠近首屏，明确“继续查看”。按真实状态区分进行中、待复核和未完成。桌面/手机与键盘/触控分别走查。若页面结构变更较大，先保留旧组件并做可回退切换。

## S2 · 输入体验

生成与优化页共用表单组装和帮助提示；在移动端显示当前分组、已填写摘要和可跳转目录；必填字段始终直接可见。提交错误聚焦到首个无效字段；可选资料解释其对输出的作用，不暗示“填了必然更高分”。优化页明确原稿解析、格式不保留、可保存/可下载的交付边界。

## S3 · 运行体验

阶段时间线采用真实事件逐步更新；断线时显示轮询同步或等待恢复，避免永久旋转。进度百分比只有服务端提供时显示；若服务端百分比不可信，用“当前阶段 + 已完成阶段数”代替。背景/返回访问后的状态一致。

## S4 · 结果与证据

结果首屏次序为：状态与下载、内容变化判定、主要修改/未解决项、教案正文、内部评分。将 JSON Pointer 转成教师可读位置名称；保留机器路径于详情或下载报告中。移动端把“修改证据”放在长教案前；生成结果不强行出现“修改稿”措辞。用真实基线与交付稿对比，不做虚假高亮。

## S5 · 产品级精修与发布前门槛

按 [S5 增量规格](./s5-product-polish.md) 先解决跨页历史、异步状态竞态和两类下载/结果失败，再修表单数据完整性与缺失值展示，最后收敛移动端阅读、焦点、触控和动效。每一项对应可运行测试，不以截图代替业务验收。本地实现结果见 [S5 验收记录](./s5-acceptance.md)；真实后端、辅助技术、200% 缩放、教师走查与公开部署性能留作独立发布门槛。

## 测试与回滚

每个切片先写关键行为测试，再改组件/CSS。运行 `npm run typecheck`、`npm test`、`npm run build`、`npm run test:e2e`；截图对比桌面和手机，并人工检查 reduced motion 与键盘。新增样式应按组件/区域收敛，不继续无约束堆大 CSS。只改前端时不触碰数据库或模型配置；若新交互失败，回退该切片而非整站。

## 发布门槛

不得以本地静态截图代替真实接口状态验收。真实数据的失败、待复核和无修改场景都必须展示正确；性能目标需在固定环境测量并记录基线与变化。人工用户测试另行组织，不在本规格中声称已完成。

## 技术依据

- [Vue Transition / TransitionGroup 官方文档](https://vuejs.org/guide/built-ins/transition)：现有 Vue 能完成状态进入、退出与列表变化；本轮只用内建功能。
- [Vue 性能指南](https://vuejs.org/guide/best-practices/performance)：需要测量生产构建和按需加载收益，不以动效数量衡量质量。
- [Motion for Vue 文档](https://motion.dev/docs/vue-animation) 与 [VueUse Motion 文档](https://motion.vueuse.org/getting-started/introduction/)：作为复杂动效候选，不纳入 S0 依赖。
- [MDN `prefers-reduced-motion`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)：减少动效回退需与系统设置一致。
- [web.dev INP 指南](https://web.dev/articles/inp)：真实用户 p75 ≤ 200 ms 是响应性目标；本地浏览器测试只能辅助诊断，不能声称已达标。
