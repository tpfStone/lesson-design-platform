# 视觉、动效与状态规范

## 视觉语言：温润的专业教学工作台

把界面看作“备课桌面 + 教案纸面”：背景是低对比暖纸色，正文用稳定的深墨色，主动作使用青绿色，琥珀色仅标示待复核/提醒，红色只用于错误。界面正文优先易读无衬线；重要课题和教案正文可用宋体。减少全大写英文标签的密度，必要时保留小字作为辅助，不让英文抢走中文任务标题。

| 层级 | 用法 | 约束 |
| --- | --- | --- |
| 页面 | 暖白背景、最大宽度容器 | 不添加持续运动的背景 |
| 工作卡片 | 细边、轻阴影、明确留白 | 同级卡片保持间距和内边距一致 |
| 主要操作 | 实心青绿、文字动词明确 | 每个区域通常只突出一个主动作 |
| 次要操作 | 描边/文字按钮 | “下载原件”不可伪装“修改稿” |
| 危险/待复核 | 有文字、图标与色彩三重信号 | 颜色不是唯一信息源 |

间距以 4/8 px 为节奏；触控目标建议至少 44×44 px，窄屏通过换行/堆叠保证空间，不以缩小文字换取布局。教案纸面与操作面板的排版要区分：前者适合长阅读，后者适合扫描与决策。

## 动效语法

动效只解释“发生了什么”，不承担装饰任务。入口过渡优先 `opacity` 与 `transform`，避免引发布局重排；相同意义用相同时间和缓动。

| 事件 | 建议时长 | 表现 |
| --- | --- | --- |
| 悬停/按下 | 120–160 ms | 颜色、1–2 px 位移或阴影，不抖动 |
| 页面/面板进入 | 180–240 ms | 淡入 + 最多 8 px 位移 |
| 折叠展开 | 160–220 ms | 清楚显示内容归属；不让焦点丢失 |
| 阶段状态改变 | 180–240 ms | 徽标与文本同时更新，不伪造进度 |
| 等待反馈 | 低频且可停止 | 仅用于真实等待；减少动效时关闭 |

不要添加无限漂浮粒子、视差、轮播、滚动劫持、按钮抖动和大面积模糊背景。`prefers-reduced-motion: reduce` 下保留即时状态与焦点可见性。组件卸载后清理计时器与观察器。

## 状态语义

所有异步区域统一考虑 `idle / loading / success / empty / error`；任务额外有 `queued / running / completed / needs_human / failed`。空数据不等于请求错误；模型评分变化不等于内容变化；“已生成候选”不等于“已交付修改稿”。状态词由业务数据驱动，前端不推断缺失事实。

## 响应式规则

- ≥1200 px：工作区与解释区双栏；结果页让教案正文优先，右侧辅助信息不喧宾夺主。
- 768–1199 px：侧边信息移到正文后或可折叠区域，避免两列都窄。
- <768 px：单列、紧凑导航、明确的分组进度；主操作在可见位置，不遮挡输入和系统键盘。
- 所有断点：长课题可换行；文件名可安全截断且提供完整名称；图表旁有文本表格。

## 微文案基调

用教师任务语言而非内部 Agent 字段名；先说结果，再说原因和下一步。失败信息不责怪用户。例如“暂时无法读取近期任务，已有任务不会丢失；请重试”优于“请求失败”。
