# S5 · 产品级精修规格（2026-09-25）

本文件是 `spec.md` 的增量。视觉方向仍为“温润的专业教学工作台”：安静、有层次、可长时间阅读；不为了炫技重写 Vue、加入大型动效库或制造虚假进度。优先级按**信任与任务完成 → 可理解性与可访问性 → 细节与动效**排序。

## 1. 必须解决的用户任务

| 编号 | 真实问题 | 交付要求 | 可执行验收 |
| --- | --- | --- | --- |
| S5-01 | 超过 12 条任务后旧任务无法找回，第一页本地筛选会误报“无结果” | 历史列表使用后端 `page/size/mode/status`；显示总数与加载更多；切换筛选清零页码，旧请求不得覆盖新筛选。 | 13+ 条任务，目标在第二页仍可到达；筛选命中第二页时不假报空；加载下一页失败不清掉已加载内容。 |
| S5-02 | 旧网络响应晚到可能让终态退回运行中；结果/产物单侧失败可能被误解释成“没有文件/仍在读取” | 状态请求按序号和生命周期保护；终态单向收敛；结果与下载分别保留成功数据、显示错误与单独重试。 | RUNNING 请求晚于 COMPLETED 返回仍保持完成；“结果成功、产物 503”及反向 503 都不隐藏另一侧数据。 |
| S5-03 | 可选条目未点“添加”即提交会丢失；数字越界仍可提交；文件错误修正后仍显示旧提示 | 条目离焦/提交入列；课时 5–240、班额 1–200 明确校验并定位；上传控件关联错误，重选有效 Word 后清除。 | 键盘/鼠标提交保留条目；0/241 课时、201 人班额不发请求；空提交→重选有效文件→错误消失。 |
| S5-04 | 缺失评分被显示为 0、缺失课时被猜成 45 分钟；失败结果出现技术英文 | 缺失写“暂不可用/待确认”，只有完整有效八维数据才画雷达；失败页区分原件、恢复记录、交付稿。 | 缺字段的结果不展示虚假 0/45；失败页无 `RUN FINISHED` 或裸露 `recovery`。 |
| S5-05 | 手机上依据帮助、后续分组和教案正文不易到达；结果证据可能被内部细节淹没 | 提交前可见精简依据提示；显示当前/下一分组；结果首屏优先交付和真实改动，提供正文跳转，审查细节可展开。 | 390 px 下完成输入与结果阅读；下载/证据/正文的阅读顺序清楚，无关键横向溢出。 |
| S5-06 | 路由焦点、键盘/表格语义、减少动效和构建大小缺少统一验收 | 标题/焦点/语义明确；五档宽度、键盘与减少动效浏览器测试；记录 JS 差异预算。 | 本地类型、格式、单测、E2E、截图和构建预算全部通过；真实屏幕阅读器与用户性能另列发布门槛。 |

## 2. 信息层级与视觉动作

- 工作台：两条主入口、近期任务及“加载更多”保持清晰的主次；列表的“当前已显示 X / 共 Y 条”来自后端，不把第一页当全部历史。
- 生成页：手机上在提交之前看到一条简洁的依据提示与真实模型费用说明；完整证据列表可展开，不能把帮助放在提交按钮之后才出现。
- 分组目录：当前分组显示 `第 n / N 部分`，横向未展示部分有明显提示和可触达的下一段；不依赖隐藏滚动条暗示可滑动。
- 优化结果：首屏保留“交付状态→下载→有无实际变化→具体改动/未解决项”；添加直达教案正文链接。内部门槛、裁决轨迹保持可展开，但不压过教师决策。
- 长阅读与状态：移动端教案正文、评分说明和阶段名称应达到可舒适阅读的字号与行距；常规文字目标对比度 ≥ 4.5:1，重要控件边界 ≥ 3:1；主要触控目标产品目标 ≥ 44×44 CSS px。
- 交互动效：只用于状态切换、焦点和按钮反馈；优先 `opacity/transform`、时长约 150–250 ms，遵循系统减少动效设置。时间线不自动“补走”未记录阶段，评分不虚假增长。

## 3. 无障碍与响应要求

- 路由切换后更新页面标题、将键盘焦点移入新页面主标题/主区域；浏览器后退与 hash 跳转不应被错误抢焦点。
- ChipInput 的可访问名称必须包含具体字段（如“课程标准”），添加/删除按钮有区分性名称；教案过程的行/列有一致的表格语义。
- 320、390、768、1280、1440 CSS px 下核心页面无非必要横向滚动；主导航、添加/删除、返回、筛选等频繁操作区域达到产品触控目标。原生 200% 浏览器缩放还需人工实测。
- 缺失数据应标缺失，不能通过默认分数、默认时长、假进度或未发生的改写动画填补。

## 4. 性能与证据边界

- 固定生产构建差异预算：入口 JS gzip ≤ 80 KB；结果主块 JS gzip ≤ 25 KB；延迟图表 JS gzip ≤ 5 KB。若超出，须在验收记录说明原因并重新评估，而非静默放宽。构建大小不是 Web Vitals。
- 公开部署后移动/桌面分别观测真实用户 p75：LCP ≤ 2.5 s、INP ≤ 200 ms、CLS ≤ 0.1；在取得真实数据前只作为目标。20 MiB Word 哈希在低端机上的响应性需单独测量后再决定是否移入 Worker。
- 截图和浏览器测试使用模拟接口时明确标识“仅验证前端状态/布局”。真实后端生成、优化、失败和恢复、教师走查、屏幕阅读器、200% 缩放是发布门槛，不可由模拟截图代替。

## 5. 技术与实施顺序

1. 先锁定上述行为测试与构建体积基线，再修列表分页、状态并发及两类终态接口错误。
2. 修表单数据完整性与可访问名称，再整理移动端帮助位置和结果阅读顺序。
3. 最后调色彩、字阶、触控/焦点与克制的动效，做五档宽度截图、键盘和减少动效回归。
4. 不修改教案模型逻辑、后端 API 或数据库；若真实后端契约与前端假设不一致，以契约为准并记录。

依据：[WCAG 2.2](https://www.w3.org/TR/WCAG22/)、[Web Vitals](https://web.dev/articles/vitals)、[Vue Transition](https://vuejs.org/guide/built-ins/transition)、[MDN 减少动态效果](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion)。其中 44 px 触控区、150–250 ms 动效是本产品目标，并非 WCAG 原文门槛。
