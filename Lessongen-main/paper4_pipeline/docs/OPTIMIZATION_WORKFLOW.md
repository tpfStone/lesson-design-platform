# 教案优化流程（与生成流程区分）

## 要解决的问题

生成任务从输入条件写出第一稿；优化任务已有一份教案，其目标不是再生成一份看起来不同的文档，而是针对可核查的问题形成**实际修改、保留原稿、说明改了什么、标出未解决问题**。内部评分变化不能单独证明优化：同一份内容重复评分也可能有分差；改变文字也不等于课堂教学效果提升。

这套流程借鉴迭代反馈与修订的研究思路（[Self-Refine](https://papers.neurips.cc/paper_files/paper/2023/hash/91edff07232fb1b55a505a9e9f6c0ff3-Abstract-Conference.html)、[IteraTeR](https://aclanthology.org/2022.acl-long.250/)）。结构化评价参考 [G-Eval](https://aclanthology.org/2023.emnlp-main.153/) 的思路；交换顺序的成对比较主要是为了减轻模型评价可能出现的位置偏差（[Judging LLM-as-a-Judge](https://papers.neurips.cc/paper_files/paper/2023/hash/91f18a1287b398d378ef22505bf41832-Abstract-Datasets_and_Benchmarks.html)）。这些论文提供设计启发，**没有**为本项目证明一个通用的“8.0 分及格线”。

## 运行路径

1. Word 导入先做 OOXML 安全检查，再按实际正文与表格顺序规范化为教案结构，保存用户原稿为 `v0`。上传稿可以使用任意教案标题和表格布局；普通超链接、外链图片及外部模板不会被访问，只记录警告后继续提取。宏、加密包和嵌入对象仍拒绝。无法可靠解析的内容不伪造为空白教案。
2. Judge 对 `v0` 做内部基线评价；三类 Critic 分别从学科事实、教学法、目标—活动—评价对齐提出可定位的意见。
3. Validator 核查意见的证据、相关性、可执行性和冲突，控制每轮进入改写的数量；不把不可执行意见交给 Rewriter。
4. Rewriter 对获准意见生成 `v1`、`v2`、`v3`（最多三轮改写）；程序比对实际内容和修改映射，拒绝只声称“已修改”的伪修改。Verifier 与硬规则检查查找回归、越界和未落实意见。
5. 每轮复评、审查并决定是否继续。优化模式使用独立的 `optimization_max_rounds=3`，不会因为两轮 Judge 分数相同但内容已变化就按“平台期”提前停止。不过模型调用、token、费用或时间预算仍可提前停止；“三轮”是上限而非保证轮数。
6. 只从结构通过、无高风险和无报告回归的版本中选择。优化模式对同分或近同分的**真实修订稿**给出待教师复核的交付优先权；不能让审查前的 `v0` 仅凭“未解决意见=0”压过已被批评过的修订稿。明显降分或风险稿不自动提升。
7. 如预算允许，对原稿与候选稿执行两次 A/B 顺序交换的独立比较。只有两次均支持有实质进步、没有回归，才形成候选偏好；分歧、失败或信息不足记为 `uncertain`，交给教师复核。成对比较仍然是模型内部证据，并不是课堂有效性实证。

## 内部达标门槛与交付状态

优化门槛与生成门槛分开配置。当前试运行参数为：候选稿总分至少 `8.0`，相对原稿至少提高 `0.2`，单个维度下降不得超过 `0.3`，最弱维度不低于通用关键维度下限；还必须确有规范教案内容变化、至少一条可追踪修改、硬规则通过、无高风险或回归。这是**软件内部停止/复核规则**，不是权威教案标准；需用教师盲评和试教资料校准阈值。尤其不应为了“过线”诱导模型虚构课程标准、教材引文或教学效果。

- **原稿**：`v0` 始终保留，不因失败而覆写。用于对照，不因原稿内部评分高就声称优化完成。
- **修订候选稿**：实际内容已改变且通过基本安全筛查；如评分近似或成对比较不确定，可下载供教师对照，但必须标为“待复核”。
- **内部达标稿与教师采纳稿**：内部达标仅表示通过软件设定的修订门槛与审查检查，可以作为“系统建议稿”展示；是否最终采纳仍应由教师决定。当前代码没有独立的教师采纳操作，页面不得把“内部达标”直接写成“教师已采纳”或“课堂效果已证实”。
- **失败或无实质变化**：如无通过校验的修订稿，状态应明确为原稿保留、改写失败或无可执行反馈；可以提供修订候选的可下载文件，但不得把它混同最终采纳稿。

结果页应同时展示原稿分、候选稿分、内容栏目级前后差异、各轮接受/未落实意见及原因、停止原因、成对比较结论和用量。分数只作内部信号：同稿分差不算修改，内容改动也不自动等于教学质量提升。

## 成本与实验边界

一次优化会比一次生成多出 Word 规范化（非可信导出时）、三类 Critic、Validator、局部改写、Judge 复评等调用。三轮上限将最坏调用和 token 用量推高；优化模式单独使用 `optimization_max_model_calls=60`、`optimization_max_total_tokens=720000`，生成模式仍沿用 `max_model_calls=42`、`max_total_tokens=360000`。费用和时间上限仍共用 `max_estimated_cost` 与 `max_runtime_seconds`。这些限制用于启动前及阶段间的预算控制；单次模型调用的实际 token/费用仍可能超过预估预留，不能将它们理解为账单上的绝对封顶。双顺序比较另需最多两次模型调用，必须计入总账；若预算不足或任何一侧失败，结论降级为不确定而不是“自动通过”。

论文实验应另行冻结任务、教案、课标与评分细则，记录 Prompt/模型版本、调用成本和所有失败运行，并安排教师盲评与使用者反馈。模型内评不能替代独立的人类评价；见关于自动评价局限的研究：[Finding Blind Spots in Evaluator LLMs with Interpretable Checklists](https://aclanthology.org/2024.emnlp-main.911/)。
