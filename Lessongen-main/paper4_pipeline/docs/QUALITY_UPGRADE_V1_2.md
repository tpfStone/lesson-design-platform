# 教案生成质量升级 v1.2

## 问题诊断

此前输出“结构完整但空洞”不是单一 Prompt 问题：交互输入可能只有科目、年级和课题；Writer 同时承担发散构思、路线选择和长篇 JSON；八维 Judge 容易把字段齐全误当质量；Rewriter 的修改声明曾被程序过早视为语义修复；Word 导出使用蓝色卡片化样式，并且按环节拆成多个二列表格，教学关系不直观。

用户提供的英语教案样例被当作只读参考。保留 A4、黑白灰、连续表格、前置分析与“教师—学生—评价”并列关系；不复制学校标识、学科网广告、二维码、具体课文或错误表达，并主动修正评价栏过窄、英文异常间距、空白反思页等问题。

## 新生成链路

```text
LessonTask
  → Design Architect：产生 2–3 个不同认知路径的候选设计并选优
  → Writer：展开选中蓝图，生成完整 LessonPlanDocument
  → 硬规则 + Judge 内容锚点评分
  → Subject/Pedagogy Critics 独立审查
  → Validator 聚焦最多 5 条高杠杆意见
  → Rewriter 在接受意见边界内做连贯修订
  → 确定性复核 + 下一轮独立审查/Judge
  → 最佳版本与 JSON/Markdown/Word 导出
```

Design Architect 是真实 DeepSeek 调用，不是硬编码模板。当前三 Critic 版本共有八类 Agent 使用 `deepseek-v4-flash`，但 Profile、Prompt、知识、可见状态、温度和 Schema 分离。

## 内容合同升级

`LessonPlanDocument` 保留旧字段并新增：

- 设计主张、驱动问题、学习轨迹；
- 可直接使用的教学材料，包括正文与答案/成功标准；
- 每个环节的学生产出、成功标准、基础支架、拓展挑战和过渡；
- 问题的预期回答、教师追问、误概念和观察证据；
- 针对不同学生反应的教师调控分支。

这些字段是向后兼容的默认可选字段，旧 JSON 可以继续读取；新 Prompt 在 `showcase` 模式下要求尽量填实。硬规则把缺失项记录为中等严重度诊断，不会让旧数据无法加载。

## Prompt 与评价策略

- Designer 温度 0.80，用于方案发散；Writer 温度 0.60，用于有边界的创作；Critic 保持低温，Validator/Judge 为 0；Rewriter 为 0.40。
- Writer 最大输出增至 12,288 tokens，Rewriter 同样增至 12,288，避免完整材料被短输出预算截断。
- 默认修订轮数由 4 调整为 2，总 token 上限增至 240,000。目标是保证两轮内容充分，而不是在不可达预算下名义设置四轮。
- Judge 除八维分数外还输出通用空话风险、学科深度、设计连贯性与材料就绪度；程序检查这些信号与分数上限是否一致。没有真实材料、学生产出、成功标准、问题链和调控时，即使章节齐全也不能高分。
- 未知语义修改只保留 `implemented`，不能由程序自动升级为 `verified_fixed`；需要下一轮独立证据确认。

## Word 输出策略

- A4 纵向、黑白灰、仿宋正文、黑体标题、英文 Times New Roman；
- 无蓝色品牌条、校徽、学校名和广告；页眉只保留学科/年级，页脚标注“AI 生成草案·须教师审核”；
- 教学过程统一为三列连续表格：教师活动，学生任务与产出，评价重点与调控；
- 表头跨页重复，允许内容较长的环节自然跨页，避免整行挤压或产生大空白；
- 真实教学材料单独完整导出，不再只显示材料名称；反思改为紧凑的课后观察区。

## 验收方式

离线测试验证设计蓝图合同、旧数据兼容、七角色配置、Prompt 哈希、生命周期语义和 A4 三列表格。Word 必须实际导出后转 PDF 逐页检查。模型内容质量仍需用同一任务做 v1.1/v1.2 对照并由教师或专家盲评；内部 Judge 分数不能替代人的实验。
